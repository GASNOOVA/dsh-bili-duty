# dsh-bili-duty · 直播值守（个人定制版）

> 挂在自己的 B 站账号上，对固定的 5 个主播做「值守 + 粉丝团每日任务」的 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）插件。
>
> 基于 [GASNOOVA/dsh-bili-live](https://github.com/GASNOOVA/dsh-bili-live)（MIT）改造：删掉评分/笔记/推送/语音转写/画面抽帧，重写为「值守型」插件。

## 它能做什么

| | 能力 | 说明 |
| --- | --- | --- |
| 🎯 | **固定 5 个主播** | 设置页维护（绑定 UID + 昵称 + 房间号），列表顺序 = 优先级；每人可单独启停、上下移。 |
| 🤖 | **自动值守** | 北京时间 08:00–24:00 每 15 分钟检查一次开播；有主播在播就进主看房挂着陪伴。 |
| 📅 | **手动计划** | 设置页给某个主播加一条「计划开播时间」：提前 10 分钟进房等待，到点没开播最多再等 10 分钟；一次性、不受工作时间限制。 |
| 🧠 | **动态识别导入** | 读取自己的 B站 空间动态，用 deepseek-flash（max 推理）识别动态里的直播预约，确认后批量导入计划。 |
| 👀 | **观看任务** | 主看房用网页端 live-trace E/X 心跳上报观看时长（每 60 秒一次，**不再拉流**）。连续 15 分钟完成 1 轮，每天最多 10 轮；亲密度按轮结算。 |
| 💬 | **发送弹幕** | ① 进房问候：每房每天一次，默认 10 条、间隔 30 秒（模板可编辑）；② 智能弹幕：默认**跟风复读**——纯本地统计时间窗口内重复最多的那句弹幕并原样复制（不调用模型，也可切自由生成），默认 5 分钟一条、每房每日 100 条上限；③ 补任务弹幕。 |
| 👍 | **点赞** | 每房每 10 分钟一轮、共 300 次；按房间下发的策略自动切批（实测每批 ≤15 次、批间隔 ≥5 秒）。 |
| 🎁 | **粉丝团灯牌打赏** | 每房每天 1 个「粉丝团灯牌」（1 电池 = 100 金瓜子）；发前查余额，余额不足直接跳过；**绝不自动充值、绝不送超过 1 电池的礼物**；默认关闭。 |
| 🔁 | **巡视补任务** | 其它在播主播有未完成的弹幕/点赞/打赏任务时，后台去补，不打断主看房的观看上报与陪伴。 |
| 📊 | **状态面板** | 每个主播今日「观看分钟 / 弹幕✓ / 点赞✓ / 打赏状态」、主看房、计划、日志。 |

**不做的事**：不评分、不写笔记、不推送私信、不做语音转写/画面抽帧、不随机巡场、不支持多账号。

## 安装

需要 DSH `>= 0.1.7-rc.1`、Node.js `>= 22`。插件零第三方依赖、无构建步骤。

```bash
# 从本地目录（开发/自用）
dsh plugin --profile web add link:/绝对路径/dsh-bili-duty

# 或从 GitHub
dsh plugin --profile web add github:你的用户名/dsh-bili-duty
```

装完刷新 DSH 页面，点左侧栏「直播值守」进入控制面板：

1. **扫码登录** B 站账号（插件自己存一份凭证，不借用别的插件）；
2. **添加 5 个主播**：填 UID，点「查询」自动补昵称/房间号；
3. 需要的话打开「打赏」开关（默认关），其余参数保持默认即可；
4. 在「值守模式」里决定自动值守还是手动计划。

插件家目录：`~/.dsh/bili-duty/`（config/state/credential/日志/附件跟踪），**凭证与状态文件不要提交到任何仓库**。识图产生的图片会写进 DSH 共享附件库（`~/.dsh/attachments/v1`），插件只回收「自己新建且 7 天内未被任何会话引用」的对象；详见「运行时文件与自动清理」。

## 两种值守模式

- **自动模式**：工作时间（默认 `08:00-24:00`，时区可选「北京时间」或「本机本地时间」）内每 15 分钟检查一遍 5 个主播；有人开播就进主看房盯到该主播下播；下播后按列表顺序切下一个在播的。
  - `workHoursTz: beijing`（默认，固定 UTC+8；宿主容器时区无关）
  - `workHoursTz: local` 或任意 IANA 时区名（如 `Europe/Berlin`）：设置页选「本机本地时间（浏览器时区）」时会自动记录浏览器时区，自动处理夏令时
- **手动计划**：一次性计划。提前 10 分钟进房（即使还没开播），到计划时间仍未开播再等 10 分钟；手动计划不受工作时间限制。

两个调度源不互斥：手动计划窗口内自动模式会让路；没有计划时自动模式照常工作。

### 从个人动态识别预约（AI）

B站 的「已预约」列表接口读不到观众侧数据（实测 `GetReserveList` 返回 `list: null`），因此改为从**个人动态**识别预约：

1. 在 B站 空间发一条包含预约信息的动态（例如「预约了嘉然今天吃什么 11月11日20:00 生日会」），**直接转发主播的预约/预告动态也可以**（会自动读取转发原文与原动态作者）；
2. 值守页面「从个人动态识别导入」点「读取我的动态」——动态列表会分成两个区域：
   - **① 预约识别（卡片）**：只识别带「直播预约卡片」的动态，结构化 JSON 直读，不用模型；
   - **② 日程表识别（图片）**：识别带图的官方日程表（一次出多条）；
3. 在「① 预约识别（卡片）」区域点「直接读取卡片」——结构化 JSON 直读，0 token、毫秒级，并自动匹配你的 5 人名单、把北京时间换算成计划时间；纯文字动态不参与预约识别（①只列带卡片的动态）。支持两种卡片：
   - 旧版 `module_dynamic.major.live_rcmd`（`live_play_info.uid/uname/title/live_start_time`）；
   - 新版 B站「直播预约」卡 `module_dynamic.additional.type=ADDITIONAL_TYPE_RESERVE`（`reserve.up_mid/title`，时间在 `desc1.text` 文案里，如「11-17 11:00 直播」，按北京时间补年份，跨年自动 +1）。
   - **图片日程表**：带图片的动态会把图片一起交给多模态模型（deepseek-flash 支持 text+image），能读出表里的日期/时间。实测一张 3000×2367 的官方日程表：11 场全部正确识别（含日期列对齐），单次调用 outputTokens≈15.7k~16.9k、总 tokens≈17.9k~18.9k、耗时约 100 秒。图片识别的输出预算是 **32000 tokens**（约 2 倍余量）；纯文字识别仍是 4000。
4. 勾选识别结果 →「导入所选为计划」（未匹配到名单的会跳过）；
5. 勾选「导入成功后删除这条转发动态」后，导入成功会自动删掉对应动态（保持空间干净）；列表里每条动态也有单独的「删除」按钮。


## 智能弹幕：跟风复读（默认，不调用模型）

- 维护最近 300 条弹幕（带时间戳）；每次发送时取最近 `aiFollowWindowMs`（默认 60 秒）窗口。
- **纯本地统计**：同一句在窗口内出现次数 ≥ `aiFollowMinCount`（默认 3 次）时，取**出现次数最多**的那一句原样复刻；同频次取最近出现的那句（更接近当下正在刷的）。
- 窗口内没有明显刷屏、或次数不够，就不发送；不会让模型生成新句子——**0 token，也不依赖模型可用性**。
- 会排除自己的弹幕、@、链接、加群/抽奖等广告文本；与上次发送相同的那句会跳过，避免连续复读同一句。
- 参数在「设置 → 直播值守 → 任务设置」里调：模式（跟风复读/自由生成）、跟风窗口秒数、最少重复次数、智能弹幕间隔、每房每日上限。
- **自由生成**（可选）：需要宿主 LLM，默认走 `deepseek-official / deepseek-flash / 推理强度 low`；跟风复读不会调用它。可在 `~/.dsh/bili-duty/config.json` 里改 `llmProvider` / `llmModel` / `llmReasoningEffort`（off/low/high/max），设置页「调试」区会显示当前实际路由。

## 每日任务口径（P0 实测）

| 任务 | 实现 | 实测结论 |
| --- | --- | --- |
| 观看直播 | 网页端 live-trace 心跳：E 建立会话 + 每 60 秒 X 签名心跳（HMAC 链）；进房/弹幕/拉流本身都不算观看时长 | 心跳成功才计秒；连续 15 分钟 = 1 轮，每日上限 10 轮（接口返回 `每日上限 X/Y`）。v1.11.0 实测 3 小时在场 0/10 → 接入后正常增长 |
| 发送弹幕 | `POST api.live.bilibili.com/msg/send`（复用原插件实现） | 问候 10 条间隔 30 秒可正常发出 |
| 点赞 | `POST /xlive/app-ucenter/v1/like_info_v3/like/likeReportV3` | 房间下发 `report_click_limit=15`、`report_time_min=5s`，300 次 = 20 批 × 15 |
| 打赏 | `POST /xlive/revenue/v2/gift/sendGoldMultiUser` | 1 电池「粉丝团灯牌」成功；参数中 `uid` 必须是送礼人自己 |

## 运行时文件与自动清理

插件自己会写的东西只有两类，都有硬上限 / 自动回收：

| 位置 | 内容 | 回收策略 |
| --- | --- | --- |
| `~/.dsh/bili-duty/live.log` | 运行日志 | 超过 512KB 自动轮转，只留最后 400 行（v1.10.0） |
| `~/.dsh/bili-duty/config.json` / `state.json` / `credential.json` | 配置、每日状态、凭证 | 不增长；写入走「临时文件 + rename」，启动时清掉残留 `*.tmp` |
| `~/.dsh/bili-duty/attachments.json` | 插件识图附件的跟踪表 | 只记录插件「新建」的图片，最多 500 条，每轮 sweep 重写 |
| `~/.dsh/attachments/v1/objects/...` | 识图时保存的动态图片（DSH 共享附件库） | 保留 7 天；删除前用 size+sha256 校验原对象，并扫描 DSH 会话日志（zstd）确认没有被引用；被引用就永久保留并移出跟踪表；扫描不完整则本轮整体跳过，宁可不删 |
| `~/.dsh/attachments/v1/tmp` | 附件库临时文件 | 超过 6 小时自动清理 |

- 触发时机：插件启动时一次、之后每 6 小时或跨日一次；只有真的发生了清理/保留动作才写日志。
- 手动入口：控制面板「调试 → 运行时文件清理 → 立即清理」；接口 `POST /api/bili-duty/runtime {action:'sweep'}`，`GET /api/bili-duty/runtime` 可查看上次结果与跟踪数量。
- 共享附件库按 sha256 内容去重。保存图片时如果对象已存在（可能是用户自己聊天的附件），插件不会把它加入跟踪表，因此不会删除这类共享对象。会话日志扫描器解析不了的压缩文件会让整轮 `deferred`，下一轮再试。
- `.probe/` 是开发期探针目录（gitignored），不属于运行时；开发完可 `rm -rf .probe`。

## 风险提示（务必阅读）

- 自动点赞 / 发弹幕 / 送礼属于对平台的**非官方自动化操作**，可能违反 B 站 用户协议，存在被限流、验证码、甚至封号的风险；本插件只在**你自己的账号**上、按你的配置执行，风险自担。
- 插件内置保守措施：随机间隔、失败即停、风控码全局暂停 10 分钟、每日上限、预算硬限制（打赏 ≤1 电池/房/天，绝不充值）。
- 建议先用「手动计划 + 默认参数」观察几天，再考虑调到默认的高频参数。

## 目录结构

```
index.js              宿主端：调度/主看房/每日任务/HTTP 路由/DSH 生命周期
client.js             浏览器端：主界面侧栏面板（自注册模块）
lib/duty-config.mjs   配置默认值与清洗（29 项）
lib/duty-state.mjs    每日任务状态（北京自然日、原子写）
lib/duty-actions.mjs  B站动作适配器（进房/点赞/礼物/钱包/粉丝牌/送礼）
lib/duty-trace.mjs    观看任务：live-trace E/X 心跳上报（WBI + HMAC 链式签名）
lib/duty-attach.mjs   运行时清理：插件识图附件的跟踪/保守回收、tmp 清理
lib/duty-watch.mjs    拉流工具（观看计时已改走 duty-trace；仅 scripts/probe.mjs 复用 getPlayUrl）
lib/live.mjs          原插件保留：房间查询、弹幕长连接、发弹幕
lib/auth.mjs          扫码登录
lib/llm.mjs           自由生成弹幕 / 动态识别（跟风复读不调用模型）
vendor/qrcode.js      登录二维码（MIT）
scripts/probe.mjs     技术探针（登录/房间/点赞/礼物/拉流，排障用）
scripts/test-trace.mjs 观看上报单元测试（假 fetch，不碰网络）
scripts/test-attach-clean.mjs 附件清退单测（28 项，临时目录 + 假会话）
docs/                 设计文档与原插件解读笔记
```

## 开发

插件零依赖、无构建。改完宿主端代码后刷新页面即可（DSH HMR 会重挂）；改 `client.js` 后刷新页面。

```bash
node --check index.js
node --check lib/duty-actions.mjs
node scripts/probe.mjs help     # 探针需要扫码登录，凭证只写本机
node scripts/test-trace.mjs    # 观看上报（live-trace E/X）：假 fetch 单测
node scripts/test-clean.mjs    # 日志轮转/计划裁剪
node scripts/test-attach-clean.mjs  # 附件保守回收（28 项断言）
node scripts/test-card-parse.mjs  # 预约卡片/时间解析
node scripts/test-client-register.mjs  # client 注册槽位冒烟
```
